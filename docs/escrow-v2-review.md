# PointEscrowV2: security and compatibility review packet

**Update (2026-10-21): shipped.** PointEscrowV2 is the escrow for new public
agreements (`--escrow-version 2`), deployed on Sepolia at `0x468170ae…` and
exercised by funded public runs ([record](../evidence/2026-10-21-public-testnet-v2.json));
the follow-up review's fixes are listed in [security](security.md). The packet
below is unchanged from the candidate.

**Status (2026-10-18): candidate.**
Nothing is deployed and nothing was broadcast. PointEscrow v1
(`contracts/src/PointEscrow.sol`) is unchanged: after `forge build` its runtime
hash is still `0x6267f59b…569a`, the value pinned by
`config/public-agreement-policy-v1.json` and by the Sepolia escrow
`0xcc0ce295627b5e15cd31a40dc6ace4bf3a35ee42`. Every client keeps v1 behavior
for an agreement without `escrow_version`. The v2 assembly has had no
independent review: this packet is the input for that review.

Throughout, *t* is Alice's adaptor witness. Revealing it on Ethereum is what
lets Bob complete his Zcash claim.

## 1. What changed

| | v1 `PointEscrow` | v2 `PointEscrowV2` |
|---|---|---|
| Verifier | `Pallas.opens`: 254 doublings and up to 254 additions, struct per step | `PallasComb.opens` with the width-4 comb: 63 doublings and up to 64 mixed additions, inline assembly, no allocation |
| Generator table | none | `PallasCombTable4` (961 bytes) created by the escrow constructor as its CREATE nonce 1. Address derived, not stored. Code hash checked at construction and at every claim |
| Order storage | 7-slot `Order` struct | one slot: `commitment(order) \| state` |
| `lock(salt, recipient, refundAt, point, termsHash)` | same ABI | same ABI, same checks, same `Locked` event |
| `claim` | `claim(bytes32 id, uint256 witness)` | `claim(bytes32 id, Order order, uint256 witness)` |
| `refund` | `refund(bytes32 id)` | `refund(bytes32 id, Order order)` |
| `withdraw` | `withdraw(address to)`: all of `credits[msg.sender]` | `withdraw(bytes32 id, Order order, address to)`: this order's amount, credited owner only |

## 2. State machine

The slot value is `orders[id]`. `C` is the commitment of the calldata order;
`LOCKED = 1`, `CLAIMED = 2`, `REFUNDED = 3`, `PAID = 4`.

| From (slot) | Call | Guard (all must hold) | To (slot) | Effect |
|---|---|---|---|---|
| `0` | `lock` | `recipient ≠ 0`, `msg.value > 0`, `termsHash ≠ 0`, `refundAt ≥ now + 300`, `point` on curve with canonical coordinates, `C ≠ 0` | `C\|1` | holds `msg.value`; `Locked` event; `id = keccak(chainid, this, msg.sender, salt)` |
| `C\|1` | `claim(id, order, t)` | `slot == C\|1`, `now < refundAt`, table code hash pinned, `0 < t < Q` and `t·G == point` | `C\|2` | `Claimed(id, t)` |
| `C\|1` | `refund(id, order)` | `slot == C\|1`, `now ≥ refundAt` | `C\|3` | `Refunded(id)` |
| `C\|2` | `withdraw(id, order, to)` | `msg.sender == order.recipient`, `to ≠ 0` | `C\|6` | pays `order.amount` to `to`; reverts entirely (slot unchanged) if the transfer fails |
| `C\|3` | `withdraw(id, order, to)` | `msg.sender == order.maker`, `to ≠ 0` | `C\|7` | same |

Any other combination reverts and changes nothing: `NotLocked`,
`NothingToWithdraw`, `NotCreditedOwner` or `InvalidOrder`. The invariants:

- A nonzero slot is never written to zero or back to `C|1`, so an id is never
  re-locked.
- `PAID` is terminal.
- Claim and refund are exclusive (both require `C|1`), and only one withdraw
  per order can succeed.
- The commitment bits never change after lock, so every later call must
  present the exact locked order.
- State is written before the only external call (`withdraw`'s transfer).
  `testReentrantWithdrawPaysOnce` shows that a reentrant withdraw sees
  `C|6|7` and reverts.

## 4. Calldata validation

Claim, refund and withdraw recompute `commitment(order)` from calldata and
compare it with the slot. Anything not bit-identical to the locked order fails:
a different maker, recipient, amount, `refundAt`, point coordinate or
`termsHash`.

- **What protects it.** The commitment is a 253-bit truncated keccak.
  Producing a different order with the same 253 bits is a second-preimage
  search, about 2^253 work.
- **Encoding.** `abi.encode` of a static struct is canonical: seven words, no
  offsets.
- **Dirty bits.** The Solidity 0.8.25 ABI decoder rejects calldata words with
  dirty high bits in `address` and `uint64` fields, so an order cannot alias
  another one by encoding (`testDirtyOrderWordsRevertOnEveryPath`, on claim,
  refund and withdraw).
- **State bits.** The slot's low three bits hold state, so the commitment never
  collides with a state value. A zero commitment is refused at lock.
- **Tests.** Every one of the seven fields, altered by one bit, reverts on
  claim, refund and withdraw:
  - in forge: `testAnyAlteredFieldRevertsOnClaimRefundAndWithdraw`;
  - through the public calldata builder against a real contract:
    `scripts/check_escrow_v2_public.py`, 7 words × 3 calls;
  - through a front-runner rewriting the pending claim:
    `run_client_swap --relay-pending-claim`.

## 5. Verifier arithmetic

`PallasComb.opens(scalar, T, comb4(table))` returns true exactly when
`0 < scalar < Q`, `T = (x, y)` with `x, y < P` on `y² = x³ + 5`, and
`scalar·G = T` for the RedPallas SpendAuth base `G`. This is the same predicate
as `Pallas.opens`.

**Comb (Lim–Lee, one table, t = 4, d = 64).** Row i holds scalar bits
`[64i, 64i + 64)`. Column j selects `idx = Σᵢ bit(j + 64i)·2ⁱ`. The table
entry is `table[idx] = Σ_{bits i of idx} 2^(64i)·G`, in affine coordinates,
for idx 1..15. The loop runs j = 63 down to 0: double (if not at infinity),
then add `table[idx]` if idx ≠ 0.

**Gather.** `((k >> j) & mask) * magic >> 189 & 15` with
`mask = 1 + 2^64 + 2^128 + 2^192` and
`magic = 1 + 2^63 + 2^126 + 2^189`. The target bits land at 189..192. The
other products fall below 189 or above 192, at distinct positions, so no carry
reaches the target. `contracts/tools/gen_comb_tables.py` checks the gather
against the direct bit sum for edge and random scalars at every width.

**Formulas.** Jacobian coordinates, a = 0:
- doubling: dbl-2009-l with D = (2X)(2Y²);
- mixed addition: madd-2007-bl with Z3 = 2·Z1·H.

Only values below 2^256 go into `mulmod` unreduced: 2X, 2Y, 3X², 2H, 2(S2−Y1),
D + p − X3. P < 2^255, so 3P < 2^256. Every stored or compared value is
reduced. Infinity is Z = 0: doubling at infinity, or for y = 0, gives Z3 = 0
automatically.

**No exceptional addition for valid scalars.** Let S_j be the accumulator's
scalar after columns 63..j, and B_j the entry's scalar. Then
S_j = 2S_{j+1} + B_j and 0 ≤ S_j ≤ k/2^j < Q. A mixed addition happens only
when S_{j+1} ≠ 0 and B_j ≠ 0.

- **H = 0 with equal points** would need 2S_{j+1} ≡ B_j (mod Q). Both sides
  lie in [0, Q), so they would be equal as integers. In base 2^64, the digits
  of 2S_{j+1} are even and those of B_j are 0 or 1, so both would be 0. That
  contradicts B_j ≠ 0.
- **H = 0 with opposite points** would need S_j ≡ 0 (mod Q), but
  0 < S_j < Q.

The code still handles both cases exactly: equal points are doubled, opposite
points give infinity.

**Final check.** `X == x·Z²` and `Y == y·Z³`, with Z ≠ 0. All arithmetic is
variable-time, on public input only (t is public once claimed).

**Table integrity.**
- `PallasCombTable4` returns a 0x00 (STOP) byte followed by the 15 entries,
  so calling it does nothing.
- The escrow constructor creates it and reverts unless its address equals
  `combTable()` (the derived CREATE address) and its code hash equals
  `PallasCombTables.CODEHASH_4`.
- `claim` checks that code hash again before using the table. That check adds
  about 100 gas: the cold access is paid once, either way.
- Code cannot change after creation: it contains no SELFDESTRUCT, and since
  EIP-6780 code cannot be removed outside its creation transaction.
- A runtime placed without running the constructor has no table. Claims then
  revert with `InvalidTable` and leave the state unchanged.

**Differential evidence** (`contracts/test/PallasComb.t.sol`, widths 4–8). The
expected points come from `PallasOracle.sol`, an independent affine
double-and-add with modexp inversion that shares no code with `Pallas.sol` or
`PallasComb.sol`. The tests:

- check all 491 table entries against `Pallas.opens`;
- cover edge scalars (1, 2, 3, Q−1, Q−2, Q−3, 2^254±1, 2^253, (Q±1)/2, …);
- cover 2^(d·i) and 2^(d·i)±1 at every column boundary;
- check that ten mutations of each valid opening are rejected;
- check fixed rejection cases;
- run three fuzz tests at 128 runs each.

`PointEscrowV2.t.sol` also fuzzes full claims (`testFuzzClaimOpensExactlyTheLockedPoint`).

## 6. Secret-exposure audit

**Rule.** t must leave Alice's process only inside her signed claim
transaction, sent with `eth_sendRawTransaction` after every check has passed.
Any RPC that executes a claim (`eth_call`, `eth_estimateGas`,
`eth_simulateV1`, tracing) hands t to the provider before her claim is
included. A leaky or malicious provider could then let Bob take the ZEC while
her claim fails or misses the deadline.

**Earlier advice was wrong and has been removed.** An earlier version of
`docs/gas-optimization.md` advised clients to `eth_call` the claim before
broadcasting. That advice is wrong and is gone. It is replaced by the local
pre-check below.

| Path | Where t is read | What can leave before inclusion | Verified in code |
|---|---|---|---|
| Local owner client `scripts/evm_participant.py` (`execute('claim')`) | `native/witness.json`, read only after `order_state == 1`, the reveal window and unspent funding are checked | Only the signed raw claim. Before it: public metadata (`eth_gasPrice`, block, nonce, balance, the `orders(id)` getter) | No `eth_call` or estimate carries claim data (grep of every client). Calldata is built in Python (`escrow_abi.calldata`, v1 `run_native_evm_gate.calldata`), never in argv. `validate_intent` decodes over stdin. The intent is fsynced before the send. Errors print a fixed message |
| Restart and replay (`evm_journal.replay`, earlier intent in `evm_participant`) | none: replays exact signed bytes | the same bytes, only inside the reveal window; never a new claim, never a refund fallback after possible exposure | `require_reveal_window`; the claim-intent file blocks native refund |
| Public owner client `scripts/public_eth_outgoing.py` | `setup-round1.json`, after an immutable decision is persisted | nothing: signing is local. The opening is checked by the native binary (`testnet-accept-opening`) | no RPC object exists in `finish()` |
| Public broadcaster `scripts/public_eth_execute.py` | none | the retained raw bytes, through `send_raw` only | the runbook's "no opening is sent to estimation" holds: `probe_sepolia.read_method` allows `eth_call` only for the `orders(bytes32)` and `credits(address)` selectors with exact shapes. It has no `eth_estimateGas`, `eth_simulateV1`, `eth_createAccessList` or trace methods. `send_once` never echoes provider exceptions |
| Bob's opening capture `scripts/public_opening.py` | from the public claim transaction or event only | n/a | the claim prefix is now version-aware (`claim_prefix`) |
| Two-party mode and browser | party apps call the owner operator → `evm_participant` (row 1) | same as row 1 | `web/*.js` shows t only after the public `claimed` event; `demo_server` exposes existence flags only |
| Coordinator-era fixtures (`run_regtest_swap`, `recover_regtest_swap`, `run_native_evm_gate`) | fixture files | `eth_sendTransaction` to the owned, isolated Anvil with an explicit 1,000,000 gas limit, so the node does not estimate | v1-only fixtures; never pointed at a provider |

**New in v2: a local claim pre-check** (`scripts/claim_precheck.py`). Before
Alice's first claim exposure, her client:

1. starts a private, throwaway Anvil on a free loopback port;
2. deploys the exact pinned v2 creation code (escrow and table);
3. locks an order to the agreed point;
4. runs `eth_call claim` with t on that node.

The witness reaches only that child process, over loopback HTTP. It never
appears in argv, at the agreed chain's node or at a provider. It runs in both
the local owner client and the public owner client. This guards against a
false rejection by the verifier, which would otherwise publish t in a reverted
claim.

**Every way a v2 claim can revert, and what prevents it before t is
exposed:**

| Revert | Pre-exposure prevention |
|---|---|
| `NotLocked` (wrong order data or state) | The client checks `orders(id) == commitment(agreed order) \| LOCKED` with the public getter. The order is computed from the signed agreement, not taken from a peer. |
| `ClaimExpired` | Reveal window: local `now + 60 < expiry`; public `first_reveal` window, `reveal_cutoff_before_expiry_seconds = 3600` |
| `InvalidTable` | `verify_code` and `inspect_v2` check the table code hash at the derived address |
| `InvalidWitness` | The native opening check, then the local pre-check against the pinned bytecode |
| Out of gas | The claim's work is almost independent of the scalar. 2^254−1 sets all 64 columns and has 32 nonzero calldata bytes, so it is the worst case: 115,893 gas on current Sepolia against the signed limit of 1,000,000 |
| A front-runner copies t | Not a loss: the copy can only settle the same order, crediting Alice; her own transaction then reverts harmlessly |

Inclusion before expiry still rests on the signed timing policy and an honest
provider, exactly as in v1. The new design adds no exposure path. The claim
calldata carries the order fields, which are already public in the `Locked`
event.

**Finding (fixed on this branch, affects main's local driver).**
`prefunding_swap.py recover` for a funded-but-never-locked trade called
`owners.native_exit`. `owner_swap` stopped re-exporting that function in
`3543669` (2026-10-15), so the never-locked funding-only refund raised
`AttributeError` before refunding. This is independent of v2. It now calls
`recover_regtest_swap.native_exit` on Alice's workspace, after the same
`native_owner.workspace` check her client runs. The public path has its own
recovery and was not affected.

## 7. Compatibility

- **Version selection.** `escrow_version` is absent in v1 agreements, and
  exactly `2` for v2.
  - Local flows create new agreements with `LATCH_ESCROW_VERSION`. The
    default is 2 on this branch; set 1 for v1.
  - Public staging: `scripts/public_agreement.py … --escrow-version 2` passes
    `escrow-v2` to the native `testnet-stage-agreement`. The Rust code then
    builds the agreement from `config/public-agreement-policy-v2.json` and
    adds `escrow_version: 2` and `escrow.table_code_hash`.
  - `testnet-check-consents` re-derives the agreement under the version it
    states. A v1 agreement is recomputed byte for byte from the v1 policy, as
    before. Unit tests: `public_consent::tests`.
- **Policy v2.** Clock, fee and observation policies are identical to v1. The
  escrow block pins the v2 creation and runtime hashes, the table code hash and
  the sha256 of the four sources. `validate_policy()` now checks both policy
  files against the checkout.
- **Fee profile.** Unchanged (`bounded-legacy-eth-v2`): its lock and claim
  limits of 1,000,000 and refund and withdraw limits of 200,000 cover v2 at
  4.6× to 8.6× the measured worst case.
- **Deployment.** One transaction (escrow plus table), measured at 7,100,182
  gas on Sepolia. `public_deploy.py --escrow-version 2` uses an 8,500,000
  limit, 1.20× that.
- **Clients changed to dispatch on the version:**
  - `evm_participant`, `evm_journal`, `owner_swap`, `prefunding_swap` and
    `run_client_swap`;
  - `party_app` and `two_party`, which also gained an optional
    `LATCH_TWO_PARTY_PORT_BASE`;
  - `demo_server`;
  - the `check_evm_reorg`, `check_native_funding_reorg` and
    `check_independent_operators` harnesses;
  - `public_agreement`, `public_deploy`, `public_evm_observation`,
    `public_eth_outgoing`, `public_eth_delivery` and `public_opening`;
  - Rust `public_consent.rs` and `main.rs`.
- **v1 bytes unchanged.** v1 calldata prefixes, deployment specs and
  observation records are byte-identical to before. Retained v1 decisions
  still compare equal.
- **Kept on v1 deliberately:** the coordinator-era fixtures
  (`run_regtest_swap`, `recover_regtest_swap`, `run_native_evm_gate`) deploy
  v1 explicitly. `scripts/measure_sepolia_gas.py` measures v1; the v2 numbers
  come from `contracts/bench/measure_sepolia_variants.py`.
- **ABI break.** The v2 ABI differs (section 1). No v1 contract or agreement
  can be moved to v2: adoption means a new deployment, new agreements and new
  public runs.

**Break-even against v1.** v2 is cheaper than v1 after 0.55 swaps on Prague
(that is, from the first swap) and after 1.76 swaps on Sepolia (from the
second). One v2 swap on Sepolia costs 869,199 gas more than one v1 swap,
including its deployment. From two swaps v2 is cheaper: 7,690,022 against
7,962,161.

**Why t = 4 is the default.** A width-8 table repays its extra deployment over
width 4 only after about 607 claims on Sepolia (93 on Prague). Sharing one
table spreads that cost but does not remove it: someone pays the extra 23.8M
gas once, and every user's claim is only about 39k cheaper. A bilateral OTC
escrow serves 1 to about 100 swaps, so t = 4 wins. One escrow per chain
serving more than about 600 swaps would favor a t = 8 table.

**The 2^24 cap.** This is relevant only to t = 8. [EIP-8037][eip8037] (Last
Call) applies the EIP-7825 cap to execution gas only and lets `tx.gas` reach
2^32−1. Sepolia currently includes transactions using 26M to 39M gas. The v2
deployment, at 7.1M, is below 2^24 in any case.

## 11. Remaining risks

1. **No independent review yet.** The verifier is new, unreviewed assembly. A
   wrong verdict is a funds-loss bug in either direction: a false accept costs
   Bob, a false reject costs Alice because the reverted claim still publishes
   t. The mitigations are the differential tests and the local pre-check, but
   neither replaces an independent review.
2. **Rules still moving.** Gas figures for current Sepolia rest on EIP-8037
   and EIP-8038, which are in Last Call and not on mainnet. Re-measure before
   any deployment. Signed limits have 4.6× to 8.6× headroom.
3. **Reading code from another contract.** The verifier reads the table with
   EXTCODECOPY, whose price is a protocol parameter.
4. **A false rejection can still publish t.** The local pre-check runs the
   pinned bytecode on Foundry's EVM, not on the target chain's client. It
   proves the logic, not the gas schedule. Gas is covered by the signed limit
   with large headroom.
5. **Clients depend on the order fields.** The hashed order makes every client
   depend on having the exact order fields. They come from the signed
   agreement and can be rebuilt from the public `Locked` event. Losing them
   blocks refund and withdraw until rebuilt; it does not move funds.
6. **Trust assumptions unchanged from v1.** The RPC provider is trusted;
   finality is a provider label; one host runs both owners in these runs.
7. **Never-locked recovery on main.** The pre-existing bug fixed in section 6
   is still present on main.

## 12. Recommendation

**v2 is a sound candidate, but it should not replace the shipped escrow until
an independent review has checked sections 2, 4, 5 and 6.** The case for it:

- the state machine is smaller than v1's (one slot, five transitions);
- every guarantee in section 3 holds with direct evidence, and the local runs
  covered success, crash after reveal, no-reveal refund, never locked and an
  adversarial front-run;
- the secret-exposure surface is unchanged from v1, which already sent nothing
  with t before inclusion, and v2 adds a pre-check against false rejections;
- per swap it uses 79% less gas on current Sepolia and 73% less on Prague, and
  it costs less than v1 from the second swap.

The remaining risk is the unreviewed comb assembly and table. If the review
passes, adoption means:

1. a new deployment with `public_deploy.py --escrow-version 2`;
2. agreements staged with `public_agreement.py --escrow-version 2`;
3. a re-run of the Sepolia simulation on the final bytecode;
4. new public success and refund runs.

Each of those is the user's decision and needs funds.
